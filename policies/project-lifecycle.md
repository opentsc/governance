# AI 原生项目生命周期

## 1. Idea

任何成员在 Discussions 的 Ideas 分类发起。目标是收集反例、相似项目、真实用户和最小验证，不投票决定“听起来是否酷”。

## 2. Proposal

证据足够后创建项目提案 Issue。至少需要一名人类发起人和一个 Agent 反方审查，明确资源、风险、两周验证和停止条件。

## 孵化准入

项目进入 Incubator 前必须同时满足：

1. 至少一名非发起人人类在提案中公开审阅；
2. 一个具名 Agent 给出反方审查，列出最强反例和失败条件；
3. 一名维护者确认没有明显重复、隐私/安全红线，资源与两周实验可承受；
4. 若需要创建组织仓库或团队，由 Organization Owner 或明确获授权的人类单独批准该权限动作。

准入是可逆的运营决定，不等于组织背书，不要求为每个实验举行核心治理表决。若项目会改变核心或结构规则，仍按 `GOVERNANCE.md` 的对应门槛另行审议。

## 3. Incubator

进入公开“Open TSC 项目孵化器”Project。建立动态使命团队；确有代码、数据或独立发布需求时，才从 `project-template` 创建沙盒仓库。发起人负责保持问题、证据和结果可见。

## 4. Active

项目已经证明真实需求、连续交付、维护者和安全边界，升级为正式活跃仓库。必须有 README、许可证或保密说明、SECURITY、贡献入口、Owner 和维护策略。

## 5. Maintenance

核心价值仍存在但主动开发降低。减少权限和自动化成本，明确响应承诺。

## 6. Archived

停止条件触发、长期无维护者或使命完成时归档。归档不是失败；必须记录结果、证据、可复用资产和重新启动条件。

## 参与与退出

成员通过动态使命加入，不被永久部门绑定。任务完成、成员退出或权限不再必要时及时回收权限，同时保留公开贡献记录。
